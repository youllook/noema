# NOEMA · Sleep — 記憶的鞏固與修剪

人腦睡覺時做兩件事：把經歷濃縮成結論（鞏固）、剪掉弱的連結（修剪）。這個技能對一個專案的記憶做同樣的事。

**守則**
- **不刪檔**：過時記憶整檔搬進 `memory/archive/`（索引 `archive/ARCHIVE.md`）。
- **用戶核准才動**：提案先列出來，用戶可以分批核准（例如「路徑失效那組全部同意」），其餘留到下次。
- **規則先、AI 後**：腳本能判斷的不要用 AI 重判，AI 只處理規則判斷不了的（重複、可壓縮）。
- 每進一個階段就跑一次腳本：它同時更新報告檔，也是 Noema 辨識階段的標記，**不要省略、不要合併成一個指令**。

腳本：`node "~/.claude/skills/sleep/noema-sleep.js" <phase> "<記憶目錄>"`
（~ 代表使用者家目錄；Windows 上是 %USERPROFILE%，實際執行時請展開成完整路徑。）
記憶目錄＝`~/.claude/projects/<專案>/memory`（預設是目前對話的專案；用戶指定別的專案就換）。
報告檔：`%LOCALAPPDATA%\Noema\sleep\<專案>.json`。開機注入預算預設 5000 tok，用戶要改就加 `--budget N`（會記住）。

## 1. 入睡 `sleep`
跑 `sleep`：備份整個記憶目錄到 `%LOCALAPPDATA%\Noema\sleep\backup\<專案>\<時間>`，記下入睡前的 token。把備份路徑告訴用戶。

## 2. 掃描 `scan`
跑 `scan`，它會輸出分組清單：
- **⚠ 又熱又可疑**：常被讀、但規則抓到問題。最危險，排最前面。
- **路徑失效**：記憶裡寫的本機路徑已不存在（網址不檢查）。
- **過了複查日**：frontmatter 有 `review: YYYY-MM-DD` 且已過期。
- **冷**：讀取紀錄窗口內（transcript 保存期間）從沒被 Read 過。冷只代表「可能用不到」，不代表錯。
- **孤兒**：冷，而且沒有任何 `[[連結]]` 連進或連出。
- **沒進索引**：檔案存在但 MEMORY.md 沒列。
- **規則沒抓到問題**：交給下一步。

## 3. AI 判斷（不另跑腳本，屬於掃描階段）
只讀需要讀的，省 token：
1. 先讀 `MEMORY.md` 索引（每條的描述），從描述找**疑似重複**（同主題多條）。
2. 只開啟：疑似重複的那幾組、路徑失效／過了複查日的、token 前幾大的熱記憶。
3. 判斷**可壓縮**：一條裡混了過程（日期＋動作的流水帳、追查經過、PR/commit 細節），可改寫成一句現況。
4. 路徑失效的，先查路徑是不是只是搬家（例如換了資料夾名），能找到新位置就建議「改正」而不是封存。

## 4. 提案 `propose`
跑 `propose`，然後在對話裡列提案表，**依原因分組，組內依 token 降冪**：

| 組 | 檔案 | tok | 讀 | 建議動作 | 一句理由 |
|---|---|---|---|---|---|

建議動作只有四種：**改正**（修失效路徑／過時事實）、**壓縮**（改寫成現況，附改寫後全文或 diff）、**合併**（說明併進哪條）、**封存**（搬 archive/）。
冷記憶不必全部封存：只建議封存「冷＋孤兒」或明顯一次性的（例如某天的 review 紀錄）；其餘冷記憶列出來讓用戶知道就好。
最後問用戶要核准哪幾組／哪幾條，然後停下來等。

## 5. 執行 `apply`
用戶核准後跑 `apply`，再逐條執行：
- 改正、壓縮、合併：用 Edit／Write 改記憶檔（Noema 會即時顯示寫入）。
- 封存：搬進 `archive/`，更新 `archive/ARCHIVE.md`，從 `MEMORY.md` 移除該行。
- 合併或封存後，掃一遍其他檔裡指向它的 `[[連結]]`，改指向新檔或去括號留純文字。
- `MEMORY.md` 索引同步更新，一行一條。

## 6. 醒來 `wake`
跑 `wake`，它會重算 token 並寫回報告。回報給用戶：
- 處理了幾條（依動作分）、沒核准而保留的有幾條。
- 開機注入 token：前 → 後（對照預算）；記憶總量：前 → 後。
- 備份位置（要復原就從那裡拷回）。
- 若 archive/ 裡有「建議可銷毀」的，**只提一句數量**，不主動銷毀。

## 銷毀（事件觸發，只限 archive/）

**只有用戶明確說「銷毀」「永久刪除封存」「清空封存」才做**，不屬於 Sleep 的五個階段，Sleep 流程中絕不自動銷毀。現役記憶不能直接銷毀：要先經 Sleep 封存進 archive/。

1. 列候選：跑 `purge`（不帶參數，只列不刪）。在 archive 放超過 30 天、窗口內沒被讀過的，會標「建議可銷毀」。
2. 用戶挑要銷毀哪些。列出最終清單，明講「永久刪除、無法從記憶目錄復原」，等用戶確認。
3. 確認後跑：`node ".../noema-sleep.js" purge "<記憶目錄>" --files a.md,b.md`
   - 必須用這支腳本刪（不要用 rm／Remove-Item）：它只接受 archive/ 底下的檔名，而且這行指令就是 Noema 演出銷毀動畫的觸發標記。
4. 從 `archive/ARCHIVE.md` 移除被銷毀的那幾行。
5. 回報：銷毀了哪幾條、省下多少 tok；提醒 Sleep 入睡時的備份仍留有副本（在 `%LOCALAPPDATA%\Noema\sleep\backup\<專案>\`），要徹底消失得另外手動刪備份。
